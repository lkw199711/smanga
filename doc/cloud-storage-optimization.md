# 网盘支持优化

网盘媒体库通过存储根访问挂载在服务器上的压缩包章节。首版以 ZIP、CBZ、RAR 和 7z 为验收范围。当前扫描把 `.cbr` 映射成 ZIP，RAR 容器的 CBR 需要修正格式识别后再纳入。网盘散图目录章节暂缓支持。本地散图的加速方案见[章节页索引](chapter-page-index.md)。[现有扩展名映射](../smanga-adonis/app/services/scan/scan_discovery_service.ts)

## 存储根与挂载状态

存储根已经让扫描路径和内容路径可以保存为相对路径。挂载点迁移时修改根路径即可。网盘策略按存储根应用，供应商预设可以给出默认值，同一供应商采用不同挂载方式时也可以单独配置。兼容现有绝对路径和 `isCloudMedia` 设置，迁移时保留已有库的行为。[路径解析](../smanga-adonis/app/services/library_path_service.ts) · [现有可用性检查](../smanga-adonis/app/services/library_availability_service.ts)

相比本地磁盘，远程挂载可能出现目录列表滞后或不完整、文件可以列出但打开阻塞、限速，以及挂载消失后只剩空目录等情况。路径存在和内容可读分别判断。

- 在现有检查上增加有限时长的目录枚举。管理界面允许选取一个样本文件测试实际打开和读取，显示最近成功时间、耗时，以及超时、未挂载、权限不足等原因。可选的根目录标记用于识别挂载到了错误目录。
- 阅读接口区分暂不可用与确认缺失。根离线、检测超时或状态未知时返回可重试的错误。确认挂载和目标目录访问正常、文件确实缺失后才返回缺失。离线时库列表和阅读记录仍可用。
- 网盘源默认只读。封面、缩略图、解压目录和临时文件保存在 Smanga 管理的本地数据目录。源文件写入或物理删除需要独立的显式授权。

## 扫描与缺失对账

现有存储根扫描能拦住完全空的结果。只列出部分目录时，未发现的漫画仍可能进入删除任务，章节也有自己的删除对账。补齐保护应覆盖定时扫描、手动扫描和完整重扫，并同时保护漫画与章节记录。[路径扫描](../smanga-adonis/app/services/scan_job.ts) · [章节扫描](../smanga-adonis/app/services/scan_manga_job.ts) · [完整重扫](../smanga-adonis/app/services/rescan_path_job.ts)

1. **发现**。按现有扫描模板枚举压缩包章节，忽略可配置的临时文件名。上传中的文件若以正式扩展名出现，等文件状态稳定后再入库。失败、超时或异常缩水写入扫描报告，并标记本轮或受影响分支结果不完整。遇到散图章节时记录跳过原因，既有记录不因支持范围调整而被判为源文件缺失。
2. **应用**。对成功读取的分支，可以写入已确认的新增项。未完成或存疑的分支保留既有记录。网盘完整重扫同样先发现、再对账，保留仍存在条目的 ID 和关联进度。
3. **确认缺失**。可信扫描中首次未发现时只登记待确认。后续独立的成功扫描结合目标路径复查和缺失宽限期，再允许软删除。记录重新出现时清除缺失标记。大批量缺失或挂载身份异常时暂停清理，报告列出待确认的范围。扫描对账只操作索引和库记录。

## 压缩包读取与本地缓存

- **限制远程 I/O**。优先替换阅读请求上的同步文件操作，再处理扫描链路。复用目录枚举结果，只对需要额外信息的条目单独查询。按存储根限制并发，阅读优先于后台扫描，临时错误有限退避重试。超时只代表调用方结束等待，仍在运行的挂载 I/O 继续占用并发额度，避免短时间内累积请求。
- **复用本地解压结果**。将同一章节的并发首读合并成一个解压任务。挂载上的随机读取不稳定时，可流式复制到本地临时文件再解压。在临时目录完成并验证后发布可读结果，失败时清理临时产物。缓存按容量淘汰，读中的文件保留到请求结束。[现有解压任务](../smanga-adonis/app/services/compress_chapter_job.ts)
- **处理换包与短时离线**。源路径变化、可核实的文件版本变化或用户要求重解压时，使旧解压产物失效。大小和修改时间可作为变化线索，同路径覆盖后仍提供强制重解压入口。网盘暂不可用时，已确认属于当前章节、本地仍完整的缓存可用于阅读。封面优先使用已缓存的本地版本。
- **流式下载**。处理读取中断和客户端取消。Range 支持按入口和底层能力提供，优先用于本地完整文件。远程挂载是否适合范围读取，以实际部署上的验证结果为准。

## 实施顺序与验收

1. 先做挂载诊断与扫描保护。验证挂载消失、目录返回空、无报错但只列出部分结果、已有章节临时缺失、网盘目录混有散图时，原有记录与进度都能保留。
2. 再做远程 I/O 限流和压缩包缓存。验证多用户同时打开同一章节只触发一次解压，读取中断不会留下可见的半成品，网盘离线时仍可读已有完整缓存，恢复后能继续读取新内容。
3. 最后完善管理界面、下载与部署说明。用至少一个实际挂载环境记录扫描耗时、首章打开耗时、缓存命中与失败原因，检查进程重启后缓存和挂载状态能正确恢复。
